= NetApp Console ローカル展開のストレージフリートについて
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
ストレージフリートは、NetApp Console ローカル展開で一緒に管理するストレージシステムをグループ化します。関連するフリートをグループ化するには、フォルダを使用します。必要なスコープで、ポリシーの適用、アクセス権限の付与、および正常性の監視を行うことができます。



[[why-fleets-matter]]
== 車両群が重要な理由

ストレージ環境が拡大するにつれて、個々のクラスターを個別に管理することは非現実的になります。フリートを使用すると、関連するストレージシステムを構造的にグループ化して、それらを一つの単位として操作できるようになります。ポリシーやアクセス制御をクラスターごとに設定する代わりに、フリートレベルで一度だけ適用します。これにより、反復的な管理作業が削減され、フリート内のすべてのクラスターが同じ基準で運用されることが保証されます。



[[how-folders-and-fleets-organize-your-resources]]
== フォルダーとフリートがリソースを整理する方法

組織のリソース階層は、フォルダとフリートで構成されています。フォルダは関連するフリートをグループ化し、フリートはストレージシステムをグループ化します。

* *組織*は階層構造の最上位レベルであり、お客様の会社を表します。
* 「フォルダー」を使用すると、関連するフリートを整理できます。たとえば、地域やビジネスユニットごとにフォルダーを作成し、各フォルダー内にフリートを作成できます。フォルダーには他のフォルダーやフリートを含めることができますが、ストレージシステムを直接関連付けることはできません。フォルダーレベルでメンバーにロールを割り当てると、メンバーはそのフォルダー内のすべてのフリートに対してそのロールを継承します。
* *Fleets* とは、管理対象のストレージシステムをグループ化する機能です。ストレージシステムをフリートに関連付け、メンバーをフリートに割り当てることでアクセス権を付与します。



NOTE: フォルダは組織管理ツールであり、組織管理者、フォルダ管理者、フリート管理者などのIAM権限を持たないメンバーには表示されません。メンバーはフォルダではなく、フリートにアクセスします。



[[fleet-examples]]
== フリートの例

フリートの編成方法は、運用モデルによって異なります。一般的なアプローチには以下が含まれます。

* *環境別* 本番環境、開発環境、テスト環境のワークロード用に、それぞれ別のフリートを作成します。これにより、本番環境のストレージはより厳格なパフォーマンスおよび容量ポリシーの下で管理されつつ、低負荷環境ではより柔軟な運用が可能になります。
* *事業部門別* 特定の部門（財務、エンジニアリング、人事など）にサービスを提供するクラスタを、専用のフリートにまとめます。そうすることで、他のフリートをそのメンバーに公開することなく、その事業部門内のチームメンバーにストレージ管理の責任を割り当てることができます。
* *場所またはデータセンター別* クラスターが複数のサイトに分散している場合、場所別に整理することで、サイトレベルの健全性を監視したり、地域固有の階層化ポリシーを適用したり、サイトごとの容量消費量を追跡したりできます。
* *アプリケーション層別* データベース、ファイル共有、仮想マシンなど、特定の種類のワークロードをホストするクラスターをグループ化することで、そのワークロードのパフォーマンスプロファイルに合わせて調整されたストレージクラスをシステム全体に適用できます。



TIP: フォルダを使用して、さらに整理のレベルを追加します。例えば、地域ごとにフォルダを作成し、各地域フォルダ内に環境ベースのフリートを作成します。



[[how-fleets-connect-to-storage-classes]]
== フリートがストレージクラスに接続する方法

ストレージクラスをフリートに関連付けると、Console のローカル展開によってそのクラスのポリシーがフリート内のすべてのストレージ プロビジョニングに適用されます。フリート内でプロビジョニングされたワークロードは、ストレージクラスで定義されたパフォーマンス、容量、および階層化ルールを自動的に継承するため、管理者はプロビジョニング時にポリシー設定を選択または確認する必要はありません。これにより、フリートは、共通の目的を果たすクラスター間で一貫したストレージ動作を適用するための主要な手段となります。



[[how-folders-and-fleets-support-access-control-and-visibility]]
== フォルダーとフリートがアクセス制御と可視性をどのようにサポートするか

フォルダとフリートは、ユーザーアクセスの境界として機能します。

* *フォルダ*レベルで役割を割り当てると、そのメンバーはフォルダ内のすべてのフリートとリソースに対してその役割を継承します。これにより、組織管理者はフォルダを作成し、フォルダ管理者またはフリート管理者の役割を割り当てることで、管理責任を委任できます。これらの管理者は、組織全体へのアクセス権を持たずに、自分のフォルダ内のすべてのフリートを管理できます。
* フリートレベルでロールを割り当てると、そのメンバーはそのフリート内のストレージシステムにのみアクセスできます。


これにより、インフラストラクチャの無関係な部分への可視性を付与することなく、ストレージ管理をチームメンバーやアプリケーション所有者に委任できます。Console のローカル展開では、フリートレベルの健全性とパフォーマンスの監視機能が提供されるため、単一のビューからフリート内のすべてのクラスターの状態を確認し、問題を早期に特定して、ワークロードに影響が出る前に対応できます。
