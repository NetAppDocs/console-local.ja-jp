= LLMを接続し、NetApp Consoleのローカル展開でNetApp Consoleアシスタントを有効にする
:hardbreaks:
:allow-uri-read: 
:nofooter: 
:icons: font
:linkattrs: 
:imagesdir: ./media/


[role="lead"]
サポートされている LLM エンドポイントを接続して、管理された自然言語ストレージガイダンスと操作を NetApp Console ローカル展開ユーザーが利用できるようにします。


NOTE: LLMをコンソールアシスタントに接続してAI機能を有効にする方法に関するこのドキュメントは、技術プレビューとして提供されています。このプレビュー版では、NetApp は一般提供開始前に、提供内容、コンテンツ、およびスケジュールを変更する権利を留保します。

.必要なアクセスロール
スーパー管理者または組織管理者。link:reference-iam-predefined-roles.html["アクセスロールについて"]。

設定後、ユーザーはダッシュボードから Console アシスタントを開き、アクセス モードを選択します。

* *読み取り専用*モードでは、アシスタントは変更を加えることなく質問に答え、ガイダンスを提供します。
* *読み取り/書き込み*モードでは、アシスタントはストレージ インフラストラクチャに対して操作を実行できます。変更を行う前に、確認と検証のための詳細情報が表示されます。ボリューム作成などの非同期操作の場合、ユーザーがアシスタントから確認できるジョブが作成されます。


LLMを接続するには、プロバイダーパスを選択し、エンドポイントの詳細とAPIキーを入力してから、*管理 > AIツール*でモデルを選択します。アシスタントのアクションは、ストレージポリシーとロールベースのアクセス制御の範囲内に留まります。



[[before-you-begin]]
== 開始する前に

コンソールアシスタントが組織で設定されたガバナンス境界内で動作できるように、プロバイダーの認証情報とエンドポイントへのアクセス権限を準備してください。

* プロバイダーの種類は、リリースとエンドポイントによってサポートされているOpenAI、OpenAI互換、またはAnthropicから選択できます。
* 選択したプロバイダ パスに対応する有効な API キー。
* プロバイダパスのエンドポイント URL。
* 必要に応じて、LLMプロバイダーアカウントのユーザー名またはID。
* コンソールのローカル展開から選択したエンドポイントへのネットワーク アクセス。


link:reference-llm-supported-models.html["NetApp Console ローカル展開でサポートされている LLM プロバイダーとモデルについて説明します"]。



[[connect-an-llm-to-netapp-console-local-deployment]]
== LLMをNetApp Consoleのローカル展開に接続する

エンドポイントの認証情報に対する管理者制御を維持しながら、検証済みのプロバイダー構成を通じてアシスタント機能を有効にします。

.手順
. NetApp Console のローカル展開にログインします。
. *Administration（管理）> AI Tools* を選択します。
. メニューを選択し、次に「編集」を選択します。
. 「プロバイダタイプ」で、プロバイダタイプを選択してください。
+
link:concept-llm-integration.html["NetApp Console ローカル展開における LLM 統合について"].

. プロバイダーエンドポイントの入力を求められた場合は、選択したプロバイダーパスのエンドポイントURLを入力してください。
. *ユーザー名*フィールドに、プロバイダのパスで必要な場合は、ユーザー名またはSSO IDを入力してください。
. *APIキー*フィールドに、選択したプロバイダーパスから取得したAPIキーを貼り付けてください。
. リストからモデルを選択してください。
. 設定内容を確認し、*保存*を選択してください。
+
設定を保存する前に、プロバイダーの種類、エンドポイントのURL、APIキー、および選択したモデルを確認してください。





[[verify-that-llm-integration-works]]
== LLM統合が正しく機能することを確認します。

アシスタントの可用性と承認動作を確認し、ユーザーが設定済みの統合機能をガバナンスされた操作に利用できるようにします。

.手順
. *コンソールアシスタント*を*読み取り専用*モードで開き、基本的なクエリを実行します。
. *コンソールアシスタント*を*読み取り/書き込み*モードで開き、ストレージを変更する操作を実行する前にユーザーの確認が必要であることを確認してください。
. アクションワークフローを必要とするユーザーが、必要なロールベースのアクセス制御を持っていることを確認してください。


検証が完了すると、ユーザーはダッシュボードからコンソールアシスタントを開き、タスクを平易な言葉で説明できるようになります。link:task-console-asst-use.html["NetApp Console アシスタントの使用方法について学ぶ"]。



[[protect-credentials-and-monitor-llm-usage]]
== 認証情報を保護し、LLMの使用状況を監視する

LLM認証情報を保護し、プロバイダーの活動を監視することで、統合の不正使用を減らし、組織のガバナンスを支援します。

* 可能な限り、Console のローカル展開統合には専用の API キーを使用してください。
* 組織のポリシーに従ってAPIキーをローテーションしてください。
* 組織のガバナンス要件に従って、プロバイダー側のAPIの使用状況とアラートを監視します。
